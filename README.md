## Как устроено

Пользователь кидает ссылку на организацию - Laravel валидирует URL, кладёт задачу в очередь - Python парсит через Selenium - результат пишется в MySQL. Фронт читает отзывы из API, по 50 на страницу.

Парсинг не делаем на каждый клик по пагинации: один раз тянем всё тк сильно быстрее будет. Иначе каждая страница - новый поход в Яндекс (а тут помимо скорости еще и риск появления капчи, хотя я на нее ни разу не попадался).

Парсер и запись в БД вынесены из контроллеров: YandexParserService, OrganizationSyncService, job SyncOrganizationReviews.

Ошибки парсинга (страница недоступна, изменилась вёрстка, упал браузер парсера) попадают в sync_status / sync_error, фронт это показывает.

## Как работает парсер

Изначально в опенсорсе нашел либу яндексового парсера на питоне, но он с 2024 года не обновлялся и не работал - я код позаимствовал и починил (переписывать на что-то другое не стал, сильно дольше вышло бы)  

В общем, это отдельный Flask-сервис, снаружи один эндпоинт GET /parse/{org_id}. Laravel дергает его из YandexParserService

Внутри поднимается хедлесс хром (undetected_chromedriver), открывается yandex.ru/maps/org/{id}/reviews/, ждём пару секунд пока отрисуется. Дальше Selenium по DOM: название организации, средний рейтинг, число оценок. Список отзывов докручивается до конца - Яндекс подгружает их лениво при скролле. Тексты с «Ещё» раскрываются кликом. С каждой карточки снимаем автора, дату, текст, звёзды.

На выходе JSON: company_info + company_reviews. Если что-то пошло не так - error и 422, Laravel кладёт это в sync_error. Пустой список отзывов - норма, ошибка только когда страница не открылась или сломались селекторы (верстка поменялась).
